# Flask core
Flask==3.1.3

# Werkzeug is Flask's WSGI/routing engine, and it is pinned here because
# this application imports it DIRECTLY, which is this file's rule for what
# gets a pin (plan step X-ae, finding N-143):
#
#   * ``app/url_converters.py`` subclasses ``werkzeug.routing.IntegerConverter``
#     to make every ``<int:...>`` path parameter an ASCII-strict row id -- so a
#     Werkzeug change to that class reaches all 123 id routes at once;
#   * ``app/routes/static_pass.py`` uses ``werkzeug.security.safe_join`` as the
#     static-file path-traversal guard, which predates X-ae and was already
#     unpinned.
#
# Flask itself only requires ``werkzeug>=3.1.0`` -- **no upper bound** -- and
# the Dockerfile installs with a plain ``pip install -r requirements.txt`` (no
# lock file, no constraints file), so every image rebuild re-resolved Werkzeug
# from PyPI and a 4.x release would have satisfied that requirement silently.
# Pinning makes a Flask bump a LOUD pip resolution conflict at build time
# instead of a routing change discovered at runtime.
Werkzeug==3.1.6
