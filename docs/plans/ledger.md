# The findings ledger

**Every open finding in every arc, in ONE table, and every row has an OWNER.** A row leaves when its
fix ships, not when a ruling settles it -- a decided-but-unbuilt defect is still ahead of you.
Closed registers stay in each arc's as-built records; ids keep their names, so a reference to any
finding resolves in whichever file holds it.

**The arc is a COLUMN, never a prefix.** The key is `(arc, id)`. Bare ids keep their exact spelling
because they are cited in commit messages (immutable), in code comments and in the archived as-built
records -- a rename would orphan every one. Where a bare id is ambiguous across the corpus the
citation must name its arc: `D4` alone names three different findings.

**The `also` column carries two DIFFERENT relations and conflating them would delete work:**

- `= arc:id` -- the SAME claim, recorded in another arc's ledger and MERGED into this row on
  2026-08-09. Two rows worded differently cannot be combined mechanically, so each merge was a
  reviewed edit; the absorbed id stays here because commit messages citing it cannot be edited.
- `~ arc:id` -- a DISTINCT finding sharing a root cause, usually cause and symptom, usually with
  different owners and different closing steps. These must NOT be merged. `N-128` says so itself:
  *its CAUSE is F-10*.

Rules for this table are `conventions.md`; the steps its owners name are `steps.md`; each arc's
argument stays in its own document.
