# The findings ledger

**Every open finding in every arc, in ONE table, and every row names a LIVE owner.** A row leaves
when its fix SHIPS, not when a ruling settles it: a decided-but-unbuilt defect is still ahead of
you; closed rows move to their arc's as-built record under the same id.
**The rules are `conventions.md`** -- rules 1, 10 and "The two relations in `ledger.md`" govern the
`owner`, the `arc` + `id` key (cite BOTH: `D4` names three different findings) and the `also`
column. The steps the owners name are `steps.md`; each arc's argument stays in its own document.

**Why ONE table rather than one per arc**, stated here because it is this registry's own reason and
was carried by the balance README until 2026-08-26 (rule 16): a finding is not arc-local. `P2` /
`F-10`, `P3` / `N-123` and `P6` / `F-12` were each ONE defect recorded in two ledgers and kept in
step by hand, and one of those pairs went unnoticed for months.

**The ledger stands at 261 rows.** By arc: balance 177, pay_calendar 41, recurrence 31, bank_import
9, credit_card 3.

**This file has NO line cap, by developer ruling 2026-08-25, and the sentence above is what replaced
it.** One finding is one line, so a cap on the file was a cap on how many defects the project was
allowed to have MEASURED: it was raised three times, and the fourth time it bound a finding was
written into a code docstring to get around it. What is graded now is that the counts are TRUE (rule
3), that no single row has swelled into its arc document's argument (rule 4's row cap), and a
runaway backstop far above any real backlog. **The pressure is meant to be the balance arc's 155 and
the 17 rows blocked on nothing but a decision, both of which are read here rather than bumped
into.** Four of those decisions were taken on 2026-08-25 and their fixes are BUILT AND UNCOMMITTED
(`pay_calendar:P74` / `P67`, `balance:N-299` / `N-300`); the rows leave here only when those commits
land, per this file's own first paragraph. A fifth, `recurrence:F-15`, was ruled and is NOT closed:
its census was wrong, the correction was wrong too, and the third measurement found 94 sites rather
than 4. **A remedy ruled against an unverified census is a remedy for the wrong problem.**
