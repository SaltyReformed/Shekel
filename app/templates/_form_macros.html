{# Reusable form field macros with built-in validation error display. Usage: {% from "_form_macros.html" import render_field, render_select, render_input_group %} All macros accept an optional `errors` dict (field_name → [error_messages]). Pass it from the route when Marshmallow validation fails: return render_template("myform.html", errors=schema_errors) **Every attribute is written LITERALLY, with Jinja only inside its quotes or as a whole-attribute {% if %} block** (plan step pay_calendar:C20, ledger row PC-515). These macros emitted their optional attributes as quoted STRINGS -- ``{{ ('placeholder="' ~ p ~ '"') if p else '' }}``, ``{{ input_attrs }}`` -- and Flask autoescapes every ``{{ }}`` in an .html template, so the browser received ``min="1" max="52"``, ``step="0.01"``, ``aria-invalid="true"``: an UNQUOTED attribute whose value carries literal quote marks, which the browser discards. Measured 2026-09-14 on every caller: no number box rendered through here had a working ``min`` / ``max`` / ``step``, so a rate of 3.25 or a YTD figure with cents failed the browser's own step check, the companion password fields carried no ``autocomplete="new-password"``, and no ARIA reached a screen reader. Marking the string safe was not the remedy -- it is the XSS hole the template hook refuses -- so ``input_attrs`` is a MAPPING now (``{"min": 1, "max": 52}``), rendered ``name="{{ value }}"`` with the VALUE escaped inside the quotes: attribute syntax from the template, attribute values through autoescape, which is the one shape that is both parsed and safe. #} {# --- Extra attributes, from a mapping --- ``attrs`` is ``{attribute name: value}`` (``none`` for nothing). Names are template literals; values are escaped inside their quotes, so a caller may pass a user-derived value without opening an injection.
