{# Settled on -- the civil day the money actually moved (ruling R-ED). Rendered ONLY for a settled transfer, because that is exactly when the fact exists. This is the ONLY correction door for the eight legacy settled rows whose day had to be invented from a pay period's start (finding N-181) -- all eight are transfer shadows, and a shadow's full-edit popover is this form. Changing it MOVES MONEY: the day is the ``entry_date`` both shadows' ledger postings are filed under, and the service re-dates them plus both endpoint accounts' anchor corrections in the same request. ``xfer.settled_on`` is the model's read of the pair's shared day (it is not a column). The box renders for ANY settled transfer, INCLUDING one whose pair carries no day -- and the condition excluded that case until a neutral review named the consequence: an undated settled transfer is exactly the shape that makes ``posting_service._entry_date`` raise ``UndatedSettleError``, i.e. a 500 on the grid, and hiding the box left that row with no way to state the day it ACTUALLY moved. A second review corrected the first's wording: a repair path did already exist, because an identity-status Save falls back to ``display_today()`` (``transfer_service._status.apply_status_to_all_three``) -- but it repairs to TODAY, inventing a day, which is the one thing this whole step exists to stop.
