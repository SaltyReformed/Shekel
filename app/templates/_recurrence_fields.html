{# The FUNDING control, and it is OFFERED for every cadence since plan step R7c-c (developer ruling 2026-08-16, plan ledger row D32). "Offered", not "rendered unconditionally": the row carries d-none here like every other cadence-dependent row on this form (#field-interval, #field-due-dom, #field-end-bound, #field-start-period), and recurrence_form.js reveals it as soon as a cadence is chosen. What D32's remedy changed is that syncPlacements reveals it for EVERY cadence instead of hiding it whenever exactly one placement was admissible -- the row no longer disappears at the moment its value is being decided for the user. The pre-script hidden state on an edit form is a property of the whole form and predates this step. It used to hide itself whenever the chosen cadence admitted one placement, which is how a bill's funding rule came to change with nothing on screen saying so: the closed set stored "every 1 month funded from the month's first paycheck" and had no quarterly twin, so raising a Monthly First rule's interval silently reassigned the placement and hid the row. Freeing the interval removes that case entirely -- the MONTH unit offers both placements at every interval -- and two cadences still admit exactly one: PERIOD, where the placement is inert because a payday resolves to its own paycheck either way, and YEAR, whose first-paycheck anchor is plan step R8's. So the row stays, the script enables the placements the chosen unit admits, and the help text says which of the two states the user is in. Both sentences are rendered HERE, as data-* attributes the script swaps between, for the reason every other copy on this form is: templates display and scripts do not author words.
